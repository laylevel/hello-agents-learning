# 第一部分：智能体与语言模型基础

# 第一章 初识智能体


## 1.1 什么是智能体？

### 1.1.1 传统视角下的智能体

在传统人工智能领域，智能体（Agent）通常指能够感知环境，并根据自身目标采取行动的系统。

一个基本智能体包含：

- 感知（Perception）
- 决策（Decision）
- 行动（Action）

智能体通过获取环境中的信息，根据设定的规则或策略做出判断，然后执行对应操作。

例如：

- 自动驾驶系统感知道路环境，并控制车辆行驶
- 游戏中的 NPC 根据玩家行为做出反应
- 机器人通过传感器感知环境并完成任务


---

### 1.1.2 大语言模型驱动的新范式

随着大语言模型（Large Language Model，LLM）的发展，智能体出现了新的实现方式。

传统智能体通常依赖：

- 固定规则
- 人工设计的流程
- 特定任务算法


而基于大语言模型的智能体，可以利用 LLM 作为核心推理模块，让系统具备：

- 理解自然语言
- 分析复杂任务
- 制定执行计划
- 调用外部工具

等能力。


简单来说：

传统智能体：

> 根据提前设计好的规则执行任务。


LLM 驱动智能体：

> 根据目标自主分析，并选择合适的方法完成任务。


---

### 1.1.3 智能体的类型

根据智能体的能力和应用场景，可以分为不同类型。


#### 1. 简单反应型智能体

根据当前环境状态直接做出反应。

特点：

- 没有长期记忆
- 不进行复杂规划
- 依赖固定规则


例如：

简单聊天机器人、自动回复系统。


#### 2. 基于模型的智能体

不仅考虑当前信息，还会结合已有状态进行判断。

特点：

- 可以保存环境信息
- 能够根据历史状态调整行为


#### 3. 目标驱动型智能体

围绕目标进行任务规划。

例如：

用户要求：

> 帮我安排一次旅游计划


智能体会拆分任务：

- 查询目的地信息
- 查询天气
- 推荐路线
- 生成方案


#### 4. 大语言模型智能体

利用 LLM 作为核心推理能力。

特点：

- 理解自然语言
- 自主规划任务
- 调用工具
- 根据反馈调整行为


---

# 1.2 智能体的构成与运行原理


## 1.2.1 任务环境定义

智能体需要运行在一个环境中。

环境指：

> 智能体进行感知和行动的外部世界。


例如：

旅游助手：

环境：

- 地图
- 天气信息
- 景点数据


编程助手：

环境：

- 代码文件
- 编译器
- 开发工具


一个完整任务通常包含：

- 目标（Goal）
- 环境（Environment）
- 行动（Action）
- 反馈（Feedback）


---

## 1.2.2 智能体的运行机制

一个智能体的基本运行流程：

1. 接收用户任务

2. 理解任务目标

3. 分析当前状态

4. 制定行动计划

5. 执行动作

6. 获取反馈

7. 根据结果继续调整


智能体不是一次性生成答案，而是通过不断循环完成任务。


---

## 1.2.3 智能体的感知与行动

智能体主要包含两个核心过程：

### 感知（Perception）

智能体获取外部信息。

例如：

- 用户输入
- 文件内容
- API返回数据
- 工具执行结果


### 行动（Action）

智能体根据判断执行操作。

例如：

- 查询数据
- 调用 API
- 修改文件
- 运行代码


智能体通过：

感知 → 思考 → 行动

不断完成任务。

创建智能体之前，需要准备：

- Python 环境

- 必要的软件依赖


基本流程：

1. 配置开发环境

2. 安装相关依赖

4. 创建第一个 Agent 程序


---

## 1.3.2 接入大语言模型

智能体需要通过大语言模型获得推理能力。

LLM 主要负责：

- 理解任务
- 生成计划
- 判断下一步操作


接入模型后，智能体拥有类似“大脑”的能力。


---

↓

决定是否调用工具：

↓

执行动作：

↓

获取结果：

↓

这个过程就是智能体的行动循环。

任务：

# 1.4 智能体应用的协作模式


## 1.4.1 作为开发者工具的智能体

智能体可以作为开发辅助工具。

例如：

- 编写代码
- 分析错误
- 生成测试代码
- 优化程序


开发者可以通过自然语言描述需求，让智能体辅助完成开发工作。


---

## 1.4.2 作为自主协作者的智能体

自主协作者智能体能够独立完成更加复杂的任务。

例如：

用户：

> 帮我完成一份市场调研报告


智能体可以：

- 搜集资料
- 分析信息
- 整理内容
- 生成报告


---

## 1.4.3 Workflow 和 Agent 的差异


### Workflow

Workflow（工作流）：

按照固定流程执行任务。


特点：

- 步骤固定
- 逻辑明确
- 可预测性强


例如：

提交订单：

填写信息 → 支付 → 发货


---

### Agent

Agent：

根据目标自主决定下一步行动。


特点：

- 可以规划
- 可以调用工具
- 可以根据结果调整


区别：

Workflow：

> 人提前设计流程。


Agent：

> 系统根据任务动态规划流程。
